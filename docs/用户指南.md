## 1. 概述

Anthill 是一个全面的远程管理平台,具有以下特性:

- **插件架构**: 支持热插拔的WASM插件
- **安全通信**: TLS 1.3 + mTLS双向认证
- **多节点管理**: 集中管理分布式节点
- **隧道支持**: 端口转发、SOCKS5、HTTP代理,支持端到端加密
- **流量混淆**: HTTP/2伪装、域前置、流量填充

### 架构图

```
┌─────────────────────────────────────────────────────┐
│              管理面板 (Web UI + API)                  │
│                     端口 3000/8080                   │
└─────────────────────────────────────────────────────┘
                           │
                     TLS / WSS
                           │
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│  节点 1     │  │  节点 2     │  │  节点 N     │
│  Linux      │  │  Windows    │  │  macOS      │
│  端口 18888 │  │  端口 18888 │  │  端口 18888 │
└─────────────┘  └─────────────┘  └─────────────┘
```

## 2. 安装

### 2.1 Docker安装 (推荐)

```bash
# 克隆或下载项目
cd anthill-admin

# 启动所有服务
docker compose up -d

# 查看日志
docker compose logs -f
```

### 2.2 手动安装

**后端:**
```bash
# 下载或构建
tar -xzf anthill-admin-backend.tar.gz

# 运行
./anthill-admin-linux-amd64

# 或使用自定义配置
ADMIN_EMAIL=admin ADMIN_PASSWORD=secret ./anthill-admin-linux-amd64
```

**运行时节点:**
```bash
# 下载或构建
tar -xzf anthill-runtime.tar.gz

# 运行并连接到管理面板
./anthill-runtime-linux-amd64 -admin wss://your-admin.example.com/ws
```

### 2.3 从源码构建

```bash
# 克隆仓库
git clone https://github.com/your-repo/anthill-admin.git
cd anthill-admin

# 构建所有组件
bash scripts/release.sh

# 输出在 dist/ 目录
```

## 3. 快速开始

### 3.1 启动管理面板

```bash
docker compose up -d admin web

# 访问界面
open http://localhost:3008
```

**默认账号:** `admin / admin123`

### 3.2 部署运行时节点

```bash
# 在目标机器上
docker run -d \
  --name anthill-runtime \
  -p 18888:18888 \
  -e ADMIN_URL=wss://your-admin.example.com/ws \
  anthill-admin/runtime
```

### 3.3 首次使用

1. 登录管理面板
2. 进入 节点 → 添加节点(如果未自动注册)
3. 进入 插件 → 上传WASM插件
4. 部署插件到节点

## 4. 管理面板

### 4.1 仪表盘

概览:
- 总节点数 / 在线节点数
- 插件总数
- 最近活动
- 系统健康状态

### 4.2 节点管理

**添加节点:**
1. 节点 → 添加节点
2. 输入名称、主机、端口
3. 点击创建

**连接到节点:**
1. 从列表选择节点
2. 点击"连接"
3. 状态变为"在线"

**节点详情:**
- 查看节点信息
- 管理已安装插件
- 执行插件命令
- 查看连接日志

### 4.3 插件仓库

**上传插件:**
1. 插件 → 上传
2. 选择WASM文件
3. 输入名称、版本、类型
4. 点击上传

**插件类型:**
- `command` - 按需执行
- `service` - 后台运行

### 4.4 用户管理

管理用户和角色:
- `admin` - 完全访问权限
- `operator` - 使用命令,有限管理权限
- `viewer` - 只读访问

### 4.5 审计日志

查看所有操作:
- 按操作、用户、时间过滤
- 导出日志 (CSV)
- 查看操作详情

## 5. 运行时节点

### 5.1 配置

环境变量:

| 变量 | 默认值 | 描述 |
|----------|---------|-------------|
| `ADMIN_URL` | `wss://localhost:8080/ws` | 管理面板WebSocket地址 |
| `NODE_ID` | 自动生成 | 唯一节点ID |
| `NODE_GROUP` | `default` | 节点组名称 |
| `LISTEN_ADDR` | `:18888` | 监听地址 |
| `TLS_CERT_FILE` | - | TLS证书路径 |
| `TLS_KEY_FILE` | - | TLS密钥路径 |
| `PLUGIN_DIR` | `./plugins` | 插件目录 |

### 5.2 连接模式

**自动模式 (默认):**
```bash
./anthill-runtime -admin wss://admin.example.com/ws
```

**主动模式 (连接管理面板):**
```bash
./anthill-runtime -mode active_tls -admin wss://admin.example.com:18888
```

**被动模式 (监听管理面板连接):**
```bash
./anthill-runtime -mode passive -listen :18888
```

### 5.3 状态指示

| 状态 | 描述 |
|--------|-------------|
| `online` | 已连接到管理面板 |
| `offline` | 已断开连接 |
| `error` | 连接错误 |


```bash
anthill-cli exec -addr localhost:18888 -plugin shell -method exec -args '{"command":"ls -la"}'
```

**列出插件:**
```bash
anthill-cli plugins -addr localhost:18888
```

## 7. 插件系统

### 7.1 内置插件

| 插件 | 类型 | 描述 |
|--------|------|-------------|
| `plugin_mgr` | 命令 | 插件生命周期管理 |
| `shell` | 命令 | 执行系统命令 |
| `file_transfer` | 命令 | 文件操作,支持断点续传 |
| `terminal` | 服务 | 交互式终端会话 |
| `proxy` | 服务 | HTTP/SOCKS5代理服务 |

### 7.2 Shell插件

```bash
# 执行命令
anthill-cli exec -plugin shell -method exec -args '{"command":"uptime"}'

# 响应
{"output": "14:32:01 up 5 days, 3:22, 2 users...", "exit_code": 0}
```

### 7.3 文件传输插件

```bash
# 列目录
anthill-cli exec -plugin file_transfer -method ls -args '{"path":"/home"}'

# 上传/下载支持断点续传
# 文件被分割为1MB块
# 传输状态存储在SQLite中
```

### 7.4 自定义WASM插件

**插件要求:**
- 导出 `invoke` 函数
- 可选导出 `alloc` 和 `dealloc` 函数

## 8. 隧道管理

### 8.1 隧道类型

| 类型 | 描述 |
|------|-------------|
| `port_forward` | 本地 → 远程端口转发 |
| `socks5` | SOCKS5代理服务器 |
| `http` | HTTP代理服务器 |

### 8.2 传输模式

| 模式 | 描述 |
|------|-------------|
| `direct` | 直连 (最快) |
| `relay` | 通过管理面板中继 (NAT穿透) |

### 8.3 端到端加密

所有隧道数据使用ChaCha20-Poly1305加密:
- X25519密钥交换
- 24小时密钥轮换
- 前向保密

### 8.4 流量混淆

**HTTP/2伪装:**
```yaml
obfuscation:
  mode: http2_masquerade
  config:
    website_root: /var/www/blog
    tunnel_endpoint: /api/v1/stream
```

**域前置:**
```yaml
obfuscation:
  mode: domain_fronting
  config:
    sni_domain: ajax.googleapis.com
    host_domain: tunnel.example.com
```

**流量填充:**
```yaml
obfuscation:
  mode: traffic_padding
  config:
    packet_size:
      min: 1024
      max: 16384
```

## 9. SSH部署

### 9.1 通过SSH部署节点

1. 管理面板 → 部署
2. 填写SSH详情:
   - 主机、端口、用户
   - 认证方式 (密码/密钥)
3. 选择运行时版本
4. 选择预装插件
5. 点击部署

### 9.2 部署进度

查看部署日志:
```bash
curl http://localhost:8080/api/deploy/{task_id}
```

### 9.3 手动SSH安装

```bash
# 上传二进制文件
scp anthill-runtime user@host:/tmp/

# SSH并安装
ssh user@host
mv /tmp/anthill-runtime /usr/local/bin/
chmod +x /usr/local/bin/anthill-runtime

# 创建systemd服务
cat > /etc/systemd/system/anthill-runtime.service << EOF
[Unit]
Description=TCP Runtime Node
After=network.target

[Service]
ExecStart=/usr/local/bin/anthill-runtime -admin wss://admin.example.com/ws
Restart=on-failure

[Install]
WantedBy=multi-user.target
EOF

systemctl enable anthill-runtime
systemctl start anthill-runtime
```

## 10. API参考

### 10.1 认证

```bash
# 登录
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'

# 响应
{"token": "eyJhbGciOiJIUzI1NiIs...", "user": {...}}
```

### 10.2 节点

```bash
# 列出节点
curl http://localhost:8080/api/nodes \
  -H "Authorization: Bearer {token}"

# 创建节点
curl -X POST http://localhost:8080/api/nodes \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{"name":"node-1","host":"192.168.1.100","port":18888}'

# 连接节点
curl -X POST http://localhost:8080/api/nodes/1/connect \
  -H "Authorization: Bearer {token}"
```

### 10.3 插件

```bash
# 列出插件
curl http://localhost:8080/api/plugins \
  -H "Authorization: Bearer {token}"

# 上传插件
curl -X POST http://localhost:8080/api/plugins \
  -H "Authorization: Bearer {token}" \
  -F "file=@plugin.wasm" \
  -F "name=my-plugin" \
  -F "version=v1.0.0" \
  -F "type=command"
```

### 10.4 部署

```bash
# 创建部署任务
curl -X POST http://localhost:8080/api/deploy \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{
    "ssh_host": "192.168.1.100",
    "ssh_user": "root",
    "ssh_password": "secret",
    "node_version": "v1.0.0"
  }'

# 查看状态
curl http://localhost:8080/api/deploy/{task_id} \
  -H "Authorization: Bearer {token}"
```
